# ZonePilot tutorial work record

Status: Stage 4 PENDING. This is an editorial outline with real build notes, not a completed or published tutorial. No dev.to URL exists yet.

ZonePilot is a business-only service-budget example for [Geoapify](https://geoapify.com). It combines a standard-library REST CLI with a documented hosted MCP path that must label its approximation. The repository remains private.

The [prompt log](PROMPTLOG.md) began before implementation. It records the requested work, spec decisions and genuine failures as they happened. [API provenance](docs/api-provenance.md) pins the read-only schema inputs and adapter authoring method. [The README](README.md) contains the reproducible offline path and pending live gates.

## Genuine build incidents available for the tutorial

1. The initial GitHub request could not reach the API from the sandbox. Authorized network access allowed the same repo inspection and clone to succeed.
2. An unquoted query URL caused zsh filename expansion to reject the spec-catalog command. Quoting the URL allowed the catalog and pinned schemas to download as data.
3. The authored fixture helper used `name` for both an address parameter and a keyword property, causing a TypeError. Renaming that parameter allowed the twenty-customer fixture to generate.

These are actual build incidents, not fabricated API failures. Controlled negative tests for no-match geocodes, malformed geometry and retries are tests and must be labeled as such. The missing Python 3.15.1 interpreter is still an unresolved verification limitation, not a fixed failure.

## Feedback for Geoapify

A hosted isoline tool would remove the primary CLI/MCP method gap. It should accept a lon/lat origin, outbound mode, seconds range, routing settings and return Polygon/MultiPolygon geometry with holes, request metadata, typed errors and bounded asynchronous status. This is a proposal, not a current capability.

The official category snapshot has no plumber-specific category. A supported trade-service taxonomy or documented alternative would make the plumbing demonstration more precise. The Isoline OpenAPI response list also omits the asynchronous 202 behavior described in prose. Documenting that schema would improve client verification.
